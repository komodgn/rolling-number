# Feature Specification: 롤링 숫자 표시 컴포넌트 (Rolling Number Display)

**Feature Branch**: `001-rolling-number-display` (스펙 디렉터리 이름. git 브랜치는 별도로 만들지 않았고 현재 `main`)

**Created**: 2026-11-09

**Status**: Draft

**Input**: User description: "결제·장바구니 화면에서 가격처럼 값이 바뀌는 숫자를, 자리별로 굴러가며 자연스럽게 전환해 보여주는 모바일(Android/iOS) UI 컴포넌트 라이브러리. 쿠폰 적용/해제, 수량 변경, 배송비 변동 시 사용자가 '얼마나, 어느 방향으로' 바뀌었는지 직관적으로 인지하게 하는 것이 목적이다." (전체 원문의 시나리오·FR·엣지 케이스·범위·성공 기준을 아래에 반영)

## 개요

이 컴포넌트는 숫자 값을 받아 로케일에 맞게 포맷해 표시하고, 값이 바뀌면 바뀐 자리만 위/아래로 굴러가게 한다. 늘어나거나 줄어든 자리는 굴러 들어오거나 나가며 페이드되고, 구분자는 제자리에서 페이드로 등장·퇴장한다. 전체 폭 변화도 부드럽게 전환된다. 사용 주체는 두 부류다.

- **앱 개발자**: 컴포넌트를 화면에 배치하고 값·포맷·스타일·타이밍을 지정한다.
- **최종 사용자**: 결제·장바구니 화면에서 금액 변화를 보고(또는 스크린리더로 듣고) 변화의 크기와 방향을 알아챈다.

결제/쿠폰 계산은 앱이 맡고, 이 컴포넌트는 표시만 담당한다.

## Clarifications

### Session 2026-11-09

- Q: 쿠폰 한 번에 여러 숫자가 동시에 바뀔 때 스크린리더는 어떻게 알려줘야 하나? → A: 단독 숫자는 각자 알리고, 같은 그룹의 숫자는 모두 안정된 뒤 "라벨 + 값"을 그룹 순서대로 모아 한 번만 알린다.
- Q: 이 라이브러리를 몇 년 전 휴대폰까지 쓸 수 있게 해야 하나? → A: Android 7.0(API 24) 이상 / iOS 15 이상. (처음에는 Android 8 / iOS 16으로 정했으나, 2026-11-10 계획 단계에서 사용자가 기술 조건으로 minSdk 24 / iOS 15+를 지정해 바꿈)

### Session 2026-11-10

- Q: 9,900 → 12,900에서 새로 생기는 자리 "1"은 어떻게 나타나야 하나? → A: 그 전환의 회전 방향으로 굴러 들어오면서 페이드 인한다(증가 시 아래에서 위로). 사라지는 자리도 그 전환의 회전 방향으로 굴러 나가며 페이드 아웃한다(감소 시 위에서 아래로).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 금액 변화를 방향 있는 롤링으로 보기 (Priority: P1)

사용자가 쿠폰을 적용하면 최종 결제 금액이 줄어들며 바뀐 자리의 숫자가 아래로 굴러간다. 수량을 늘리면 금액이 올라가며 숫자가 위로 굴러간다. 자릿수가 늘면(9,900 → 12,900) 새 자리가 같은 방향으로 굴러 들어오며 나타나고 전체 폭이 부드럽게 넓어진다.

**Why this priority**: 라이브러리의 존재 이유다. 이것만 있어도 "얼마나, 어느 방향으로 바뀌었는지" 알려주는 가치가 생긴다.

**Independent Test**: 숫자 하나를 배치하고 값을 증가·감소·자릿수 변화 시나리오로 바꿔 가며, 각 자리의 회전 방향, 등장·퇴장 요소, 폭 전환을 확인한다.

**Acceptance Scenarios**:

1. **Given** ₩15,000 표시 중, **When** 값이 12,000으로 바뀌면, **Then** 바뀐 자리(5→2)만 아래로 굴러가고 바뀌지 않은 자리와 구분자는 움직이지 않는다.
2. **Given** ₩9,900 표시 중, **When** 값이 12,900으로 바뀌면, **Then** 천의 자리 9→2가 위로 굴러가고 만의 자리 "1"이 같은 방향(아래에서 위로)으로 굴러 들어오며 페이드 인되고, 기존 구분자는 그대로 유지된 채 함께 이동하고 전체 폭이 튀지 않고 부드럽게 넓어진다.
3. **Given** ₩900 표시 중, **When** 값이 1,900으로 바뀌면, **Then** "1"은 위로 굴러 들어오며 페이드 인되고, 천 단위 구분자 ","는 제자리에서 페이드 인된다.
4. **Given** ₩12,900 표시 중, **When** 값이 9,900으로 바뀌면, **Then** 만의 자리 "1"이 아래로 굴러 나가며 페이드 아웃되고 2→9는 아래로 굴러가며(값 감소) 폭이 부드럽게 줄어든다.
5. **Given** 화면에 처음 진입, **When** 컴포넌트가 처음 값을 표시하면, **Then** 애니메이션 없이 바로 값이 보인다.
6. **Given** ₩12,900 표시 중, **When** 같은 값 12,900이 다시 들어오면, **Then** 아무 애니메이션도 일어나지 않고 시작/종료 이벤트도 발생하지 않는다.

### User Story 2 - 로케일·통화 포맷으로 표시 (Priority: P1)

앱 개발자는 값과 포맷(통화, 소수 자릿수, 구분자, 퍼센트, 축약 표기, 접두·접미)만 지정해 한 줄로 컴포넌트를 쓴다. 로케일을 지정하지 않으면 기기 로케일을 따른다.

**Why this priority**: 결제 화면은 포맷이 맞지 않으면 쓸 수 없다. 롤링과 함께 MVP의 필수 조건이다.

**Independent Test**: 애니메이션을 끈 상태에서 여러 로케일·포맷 조합으로 표시 문자열을 기대값 표와 비교한다.

**Acceptance Scenarios**:

1. **Given** 로케일 ko-KR, 통화 KRW, **When** 12900을 표시하면, **Then** "₩12,900"으로 보인다.
2. **Given** 로케일 en-US, 통화 USD, **When** 1234.56을 표시하면, **Then** "$1,234.56"으로 보인다.
3. **Given** 로케일 de-DE, 통화 EUR, **When** 1234.56을 표시하면, **Then** "1.234,56 €"로 보인다.
4. **Given** 퍼센트 포맷, **When** 0.125를 소수 1자리로 표시하면, **Then** 해당 로케일 규칙의 퍼센트(예: en-US "12.5%")로 보인다.
5. **Given** 축약 포맷, en-US, **When** 1200을 표시하면, **Then** "1.2K"로 보인다.
6. **Given** 접미 "/월"을 지정, **When** 값을 표시하면, **Then** 포맷된 숫자 뒤에 "/월"이 붙는다.
7. **Given** 로케일 미지정, **When** 기기 로케일이 ko-KR이면, **Then** ko-KR 규칙으로 표시된다.

### User Story 3 - 빠른 연속 변경에도 끊김 없는 전환 (Priority: P2)

사용자가 쿠폰을 빠르게 연타해 애니메이션 도중 값이 다시 바뀌어도, 각 자리는 현재 보이는 위치에서 새 목표값으로 끊김 없이 이어진다.

**Why this priority**: 실제 결제 화면에서 흔한 상황이다. 깜빡임이나 처음부터 다시 시작하는 모습은 신뢰를 떨어뜨린다.

**Independent Test**: 애니메이션 진행 중(예: 40% 지점)에 새 값을 주입하고, 자리 위치·투명도·폭이 순간 이동하지 않고 연속적으로 변하는지 프레임 단위로 확인한다.

**Acceptance Scenarios**:

1. **Given** 15,000 → 12,000 전환 중, **When** 값이 15,000으로 되돌아가면, **Then** 굴러가던 자리가 현재 위치에서 방향을 바꿔 15,000으로 돌아가고, 위치가 순간 이동하지 않는다.
2. **Given** 9,900 → 12,900 전환 중("1"이 페이드 인 중), **When** 값이 9,900으로 되돌아가면, **Then** "1"은 현재 투명도에서 다시 페이드 아웃되고, 같은 자리에 요소가 중복으로 생기지 않는다.
3. **Given** 연속으로 5번 값이 바뀌는 상황, **When** 마지막 값에서 안정되면, **Then** 종료 이벤트는 마지막 값에 도달했을 때 한 번만 발생한다.

---

### User Story 4 - 인접한 여러 숫자의 위치 변화 동기화 (Priority: P2)

원가 / 할인액 / 최종가처럼 여러 숫자가 한 줄이나 인접 위치에 있을 때, 한 숫자의 폭 변화 때문에 다른 숫자가 밀리면 그 이동도 같은 타이밍으로 함께 움직인다.

**Why this priority**: 한 줄 가격 요약에서 옆 요소가 순간 이동하면 롤링 효과가 무너진다. 다만 단일 숫자 사용보다 빈도가 낮다.

**Independent Test**: 같은 그룹으로 묶은 숫자 세 개를 한 줄에 놓고 가운데 숫자의 자릿수를 늘려, 오른쪽 숫자의 위치 이동이 가운데 숫자의 폭 전환과 같은 시작 시점·곡선으로 진행되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 한 줄에 그룹으로 묶인 [원가][할인액][최종가], **When** 할인액이 -₩900에서 -₩1,900으로 바뀌면, **Then** 최종가는 순간 이동하지 않고 할인액의 폭 전환과 같은 레이아웃 타이밍으로 밀려난다.
2. **Given** 같은 그룹의 두 숫자가 동시에 바뀜, **When** 전환이 진행되면, **Then** 두 숫자의 레이아웃 이동은 같은 시점에 시작해 같은 곡선으로 진행된다.
3. **Given** 그룹으로 묶지 않은 인접 숫자, **When** 한 숫자의 폭이 바뀌면, **Then** 다른 숫자의 위치는 일반 레이아웃 규칙대로 바뀐다(동기화 보장 없음).

---

### User Story 5 - 접근성: 최종 값만 낭독, 동작 줄이기 존중 (Priority: P1)

스크린리더 사용자는 애니메이션 중간 값이 아닌 포맷된 최종 값만 한 번 듣는다. 기기에서 "동작 줄이기"를 켠 사용자에게는 애니메이션 없이 값이 즉시 바뀐다.

**Why this priority**: 결제 화면에서 접근성은 타협할 수 없는 요구이고, 중간 값 낭독은 잘못된 금액 안내가 된다.

**Independent Test**: 스크린리더를 켜고 값을 바꿔 낭독 횟수와 내용을 기록한다. 동작 줄이기를 켜고 값을 바꿔 애니메이션이 없는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 스크린리더 활성, **When** ₩15,000 → ₩12,000으로 바뀌면, **Then** "₩12,000"에 해당하는 값만 한 번 낭독되고 중간 값은 낭독되지 않는다.
2. **Given** 스크린리더 활성, 빠른 연속 변경(15,000 → 12,000 → 9,000), **When** 값이 안정되면, **Then** 마지막 값 "₩9,000"만 한 번 낭독된다.
3. **Given** 스크린리더 포커스가 컴포넌트에 있음, **When** 애니메이션 중 값을 읽으면, **Then** 목표 값(최종 값)을 읽는다.
4. **Given** OS의 동작 줄이기 켜짐, 개발자가 무시하도록 설정하지 않음, **When** 값이 바뀌면, **Then** 애니메이션 없이 즉시 새 값이 표시된다.
5. **Given** OS의 동작 줄이기 켜짐, 개발자가 무시하도록 설정, **When** 값이 바뀌면, **Then** 일반 애니메이션이 재생된다.
6. **Given** 스크린리더 활성, 같은 그룹의 [할인액][최종가]에 각각 라벨 "할인액", "최종가"가 지정됨, **When** 쿠폰 적용으로 두 값이 동시에 바뀌면, **Then** 둘 다 안정된 뒤 "할인액 -₩1,900, 최종가 ₩12,900"이 한 번만 알려지고, 숫자별 개별 알림은 없다.
7. **Given** 같은 그룹에서 최종가만 바뀜, **When** 안정되면, **Then** 바뀐 숫자만 "최종가 ₩12,900"으로 한 번 알려진다.

### User Story 6 - 개발자 제어: 방향·타이밍·스타일·이벤트·끄기 (Priority: P3)

앱 개발자는 회전 방향 규칙, 레이아웃 이동·숫자 회전·페이드 각각의 속도와 곡선, 글꼴·크기·색상·굵기, 페이드 마스크 크기를 조절하고, 애니메이션 시작/종료 시점을 받아 다른 UI와 연동하며, 필요하면 애니메이션을 끈다.

**Why this priority**: 기본값만으로도 MVP 가치는 성립한다. 커스터마이즈는 디자인 시스템에 맞추기 위한 2차 요구다.

**Independent Test**: 각 옵션을 하나씩 바꿔 기본값 대비 동작 차이를 확인하고, 이벤트 수신 순서와 횟수를 기록한다.

**Acceptance Scenarios**:

1. **Given** 방향 "항상 위", **When** 값이 감소하면, **Then** 바뀐 자리가 모두 위로 굴러간다.
2. **Given** 방향 "자리별 독립", **When** 19 → 21로 바뀌면, **Then** 십의 자리 1→2는 위로, 일의 자리 9→1은 아래로 굴러간다.
3. **Given** 애니메이션 진행 중, **When** 개발자가 애니메이션을 끄면, **Then** 진행 중 전환이 즉시 최종 상태로 완료되고 종료 이벤트가 발생한다.
4. **Given** 시작/종료 이벤트 구독, **When** 값이 한 번 바뀌어 애니메이션되면, **Then** 시작 1회, 종료 1회가 이 순서로 발생한다.
5. **Given** 기본 스타일, **When** 숫자가 회전하면, **Then** 모든 숫자가 같은 폭을 차지해 회전 중 좌우로 흔들리지 않는다.

### Edge Cases

모든 규칙은 아래 "전환 규칙" 요구사항(FR-006 ~ FR-012)을 따르며, 각 경우의 기대 동작은 다음과 같다.

- **0 ↔ 양수** (0 → 5,000): 일의 자리 "0"은 대응 자리 "0"과 같으므로 그대로 두고, 늘어난 자리("5", "0", "0")는 위로 굴러 들어오며 페이드 인, 구분자는 제자리 페이드 인, 폭은 부드럽게 넓어진다. 반대 방향(5,000 → 0)은 사라지는 자리가 아래로 굴러 나가며 페이드 아웃된다.
- **양수 ↔ 음수** (500 → -300): 부호 "-"가 로케일이 정한 위치에 페이드로 등장하고, 바뀐 자리는 값의 방향(감소 → 아래)으로 굴러간다. 음수 → 양수는 부호가 페이드 아웃되고 숫자는 위로 굴러간다. 부호와 통화 기호의 상대 위치(예: "-₩300")는 로케일 규칙을 따른다.
- **소수 자릿수 변화, 같은 값** (12.5 → 12.50, 포맷 변경으로 생김): 숫자 값이 같으므로 굴러가는 자리는 없고, 늘어난 소수 자리 "0"만 제자리에서 페이드 인된다(값 변화가 없어 회전 방향이 없으므로 굴러 들어오지 않음).
- **소수 자릿수 변화, 다른 값** (12.99 → 13, 최소 소수 자리 0인 포맷): 소수점은 제자리 페이드 아웃, 소수 자리 "9","9"는 위로 굴러 나가며 페이드 아웃, 일의 자리 2→3은 위로 굴러가고, 십의 자리 "1"은 그대로다.
- **매우 큰 수** (1,000,000,000 이상): 최소 정수 15자리까지 정밀도 손실 없이 표시하고, 구분자 규칙은 일반 수와 같다.
- **축약 단위 변화** (999 → 1K): 표시 문자열 기준으로 소수점에 맞춰 정렬해 매칭한다. 일의 자리 위치의 9→1은 값 방향(증가 → 위)으로 굴러가고, 나머지 "9","9"는 위로 굴러 나가며 페이드 아웃, 단위 "K"는 제자리 페이드 인된다. 단위 자체가 바뀌는 경우(1.2K → 1.2M)는 단위 문자를 교체 페이드한다.
- **같은 값 재입력**: 애니메이션도 이벤트도 낭독도 없다.
- **런타임 로케일 변경**: 값 변화가 아닌 표시 형식 변화이므로 굴러가지 않고 새 형식으로 즉시 교체한다. 폭은 즉시 반영된다.
- **첫 표시**: 기본은 애니메이션 없이 표시한다. 개발자가 "첫 표시 애니메이션"을 켜면 모든 숫자 자리가 위로 굴러 들어오며 페이드 인되고(방향 모드가 "항상 아래"면 아래로), 나머지 문자는 제자리 페이드 인된다.
- **리스트 셀 재사용/스크롤**: 컴포넌트가 다른 항목에 다시 연결되면(항목 식별자 변경) 첫 표시와 같이 애니메이션 없이 즉시 표시하고, 이전 항목의 진행 중 전환과 이벤트는 취소된다. 같은 항목에서 화면에 보이는 동안 값이 바뀌면 정상 애니메이션한다. 화면 밖에서 값이 바뀌면 다시 보일 때 최종 값으로 바로 표시된다.
- **접두·접미 문자열 변경** ("/월" → "/년"): 이전 문자열은 페이드 아웃, 새 문자열은 페이드 인되고 폭은 부드럽게 전환된다. 숫자 자리는 숫자 값 변화 규칙을 따로 따른다.
- **유효하지 않은 값** (숫자가 아님, 무한대): 표시를 바꾸지 않고 마지막 유효 값을 유지하며, 개발 중 경고를 남긴다.
- **애니메이션 도중 동작 줄이기 설정이 켜짐**: 진행 중 전환이 즉시 최종 상태로 완료된다(FR-011과 동일).

## Requirements *(mandatory)*

### Functional Requirements

**값 표시와 포맷**

- **FR-001 값 표시**: 컴포넌트는 숫자 값을 받아 표시하고, 값이 바뀌면 개발자가 별도로 호출하지 않아도 전환 애니메이션을 시작해야 한다. 금액 표시에서 오차가 생기지 않도록 정확한 10진 값을 받을 수 있어야 한다.
- **FR-002 포맷**: 통화(최소 KRW, USD, EUR, JPY 지원), 최소/최대 소수 자릿수, 천 단위 구분자 사용 여부, 퍼센트, 축약 표기(예: 1.2K)를 지원해야 한다. 반올림은 기본적으로 사사오입(half-up)이며 바꿀 수 있어야 한다.
- **FR-003 로케일**: 로케일을 지정할 수 있어야 하고, 미지정 시 기기 로케일을 따라야 한다. 표시 형식(구분자, 통화 기호의 위치·간격, 부호 위치, 축약 단위)은 로케일 규칙을 따른다. 로케일 형식은 각 OS가 제공하는 로케일 포맷 규칙을 그대로 사용한다. 따라서 공백 문자 종류나 통화 기호 간격 같은 세부는 플랫폼이나 OS 버전에 따라 조금 다를 수 있으며, 이는 허용된다. 숫자, 소수점·천 단위 구분자의 위치, 부호의 존재는 같은 값·포맷·로케일에서 두 플랫폼이 같아야 한다.
- **FR-004 접두/접미**: 임의의 접두·접미 문자열을 붙일 수 있어야 한다(예: "~", "/월"). 접두·접미는 회전하지 않는 고정 텍스트로 취급한다.

**전환 규칙**

- **FR-005 방향(trend)**: 방향 모드는 다음 네 가지다. 기본은 "자동"이다.
  - **자동**: 값이 증가하면 바뀐 모든 자리가 위로, 감소하면 아래로 굴러간다.
  - **항상 위** / **항상 아래**: 값 변화와 상관없이 고정 방향.
  - **자리별 독립**: 각 자리가 자기 숫자의 증감에 따라 방향을 정한다(숫자 증가 → 위, 감소 → 아래).
- **FR-006 자리 매칭**: 이전·새 표시 문자열은 소수점(로케일 소수 구분자) 위치를 기준으로 정렬해 매칭해야 한다. 정수부는 소수점에서 왼쪽으로 몇 번째인지, 소수부는 오른쪽으로 몇 번째인지로 짝을 짓는다. 소수점이 없으면 정수부 끝을 기준으로 삼는다. 매칭은 숫자의 실제 자리값이 아닌 표시 문자열 위치 기준이다(축약 표기 포함).
- **FR-007 자리 전환**: 매칭된 자리의 숫자가 같으면 움직이지 않고, 다르면 FR-005 방향으로 한 칸 굴러간다(이전 숫자는 나가고 새 숫자가 들어옴. 중간 숫자는 거치지 않음).
- **FR-008 등장·퇴장**: 짝이 없는 **숫자 자리**는 이번 전환의 회전 방향으로 굴러 들어오며 페이드 인하고, 같은 방향으로 굴러 나가며 페이드 아웃해야 한다. 예를 들어 위 방향이면 아래에서 들어오고 위로 나간다. "자리별 독립" 모드에서는 등장·퇴장 자리가 값 전체의 증감 방향을 따른다. 숫자 값이 같고 표시만 바뀐 경우(FR-012)에는 회전 방향이 없으므로 제자리 페이드만 한다. 천 단위 구분자, 소수점, 부호, 축약 단위, 바뀐 접두·접미는 움직이지 않고 제자리에서 페이드로 등장·퇴장한다. 구분자는 소수점 기준 같은 위치에 이전·새 문자열 모두에 있으면 유지된다.
- **FR-009 폭 전환**: 전체 폭 변화와 그에 따른 각 요소의 위치 이동은 순간 이동 없이 부드럽게 애니메이션되어야 한다.
- **FR-010 타이밍**: 레이아웃 이동, 숫자 회전, 페이드 세 가지 각각의 속도와 곡선을 따로 설정할 수 있어야 하며, 기본값은 스프링 계열의 자연스러운 곡선이어야 한다. 기본 전환은 사용자가 인지하기에 충분하면서도 결제 흐름을 방해하지 않도록 약 0.3~0.6초 안에 시각적으로 안정되어야 한다.
- **FR-011 중단 처리**: 애니메이션 도중 새 값이 들어오면 각 요소(자리 위치, 투명도, 폭)는 현재 보이는 상태에서 새 목표로 연속적으로 이어가야 한다. 방향은 직전 목표값 대비 새 목표값으로 다시 정하고, 퇴장 중이던 요소가 다시 필요해지면 중복 생성 없이 그 요소를 되돌려야 한다.
- **FR-012 같은 값**: 표시 문자열이 이전과 같으면 아무 전환도 하지 않아야 한다. 숫자 값은 같지만 표시 문자열이 다르면(예: 12.5 → 12.50) 문자열 차이만 FR-008 규칙으로 전환한다.
- **FR-013 첫 표시와 식별자 변경**: 첫 표시는 기본적으로 애니메이션 없이 해야 하며, 개발자가 첫 표시 애니메이션을 켤 수 있어야 한다. 개발자는 항목 식별자를 지정할 수 있고, 식별자가 바뀌면 첫 표시처럼 처리해야 한다(리스트 셀 재사용 대응).
- **FR-014 로케일·포맷 런타임 변경**: 숫자 값은 그대로이고 로케일만 바뀌면 굴러가지 않고 즉시 새 형식으로 바뀌어야 한다.

**그룹**

- **FR-015 그룹 동기화**: 여러 숫자 컴포넌트를 하나의 그룹으로 묶을 수 있어야 하며, 같은 그룹 안에서 한 컴포넌트의 폭 변화로 생기는 다른 그룹원의 위치 이동은 같은 시작 시점과 레이아웃 타이밍으로 함께 진행되어야 한다.

**애니메이션 제어와 접근성**

- **FR-016 애니메이션 끄기**: 개발자가 애니메이션을 끌 수 있어야 하고, 끄는 순간 진행 중인 전환은 즉시 최종 상태로 완료되어야 한다. 꺼진 동안 값 변경은 즉시 반영된다.
- **FR-017 동작 줄이기**: 기본적으로 OS의 동작 줄이기 설정을 따라 켜져 있으면 애니메이션 없이 즉시 바꿔야 한다. 설정이 앱 실행 중 바뀌어도 반영되어야 한다. 개발자는 이 설정을 무시하도록 지정할 수 있어야 한다.
- **FR-018 접근성 값 노출**: 보조기술에는 항상 포맷된 최종(목표) 값만 하나의 텍스트로 노출해야 하며, 개별 자리·구분자·중간 값은 노출하지 않아야 한다.
- **FR-019 변경 낭독**: 값이 바뀌면 전환이 안정된 뒤 최종 값을 한 번 알려야 한다. 안정되기 전에 값이 다시 바뀌면 마지막 값만 한 번 알린다. 개발자는 숫자마다 접근성 라벨(예: "최종가")을 지정할 수 있고, 지정하면 "라벨 + 값"으로 알린다. 개발자는 변경 알림을 끌 수 있어야 한다(기본 켜짐).
- **FR-019a 그룹 알림 병합**: 같은 그룹(FR-015) 안의 숫자들은 개별 알림을 내지 않는다. 대신 그룹 안에서 값이 바뀐 모든 숫자가 안정된 뒤, 바뀐 숫자만 그룹에 정해진 순서대로 "라벨 + 값"을 이어 붙여 한 번의 알림으로 알린다. 알림 대기 중 그룹 안 다른 숫자가 또 바뀌면, 그 숫자까지 안정된 뒤 한 번만 알린다. 알림을 끈 숫자는 병합 알림에서도 빠진다.

**이벤트와 스타일**

- **FR-020 이벤트**: 앱은 전환 시작과 종료 시점을 받을 수 있어야 한다. 정지 상태에서 값이 바뀌어 애니메이션이 시작될 때 시작 1회, 모든 요소가 마지막 목표에 안정되었을 때 종료 1회가 발생한다. 중단·이어가기(FR-011)는 추가 시작/종료를 만들지 않는다. 애니메이션 없이 반영된 변경(첫 표시, 같은 값, 끄기, 동작 줄이기)은 이벤트를 만들지 않으며, 진행 중 전환이 끄기로 강제 완료되면 종료가 발생한다. 식별자 변경으로 취소된 전환은 종료를 발생시키지 않는다.
- **FR-021 스타일**: 글꼴, 크기, 색상, 굵기를 지정할 수 있어야 한다. 숫자 폭은 기본적으로 모든 숫자가 같은 폭을 차지해 회전 중 흔들리지 않아야 하며, 개발자가 이를 끌 수 있어야 한다.
- **FR-022 페이드 마스크**: 굴러가는 자리의 위·아래 경계에 적용되는 페이드 마스크의 크기를 조절할 수 있어야 하며 0(마스크 없음)도 허용한다.

**플랫폼 동등성과 사용성**

- **FR-023 플랫폼 동등성**: 같은 이전·새 표시 문자열과 방향 설정이 주어지면 Android와 iOS는 같은 전환 계획(각 요소의 회전 여부와 방향, 등장·퇴장, 유지되는 구분자)을 만들어야 한다. 동등성 보장 대상은 전환 규칙이며, 표시 문자열의 세부(FR-003에서 허용한 OS별 차이)는 대상이 아니다.
- **FR-024 최소 사용**: 앱 개발자는 값과 포맷만 지정해 한 줄 선언으로 컴포넌트를 쓸 수 있어야 하며, 나머지 옵션은 모두 기본값을 가진다.
- **FR-025 지원 OS 범위**: Android 7.0(API 24) 이상, iOS 15 이상에서 이 문서의 모든 요구사항이 동작해야 한다. 지원 범위 안의 모든 OS 버전에서 기능 차이가 없어야 한다.

### Key Entities

- **표시 값 (Value)**: 표시할 정확한 10진 숫자. 부호, 크기, 소수부를 가진다.
- **포맷 설정 (Format)**: 스타일(일반/통화/퍼센트/축약), 통화 코드, 최소·최대 소수 자릿수, 구분자 사용 여부, 반올림 방식, 로케일, 접두·접미.
- **표시 문자열 (Formatted Text)**: 값과 포맷으로 만들어진 문자열. 각 글자는 숫자, 소수점, 구분자, 부호, 통화 기호, 축약 단위, 접두·접미 중 하나로 분류된다.
- **전환 계획 (Transition Plan)**: 이전·새 표시 문자열을 FR-006 규칙으로 매칭한 결과. 요소마다 유지/회전(방향)/등장/퇴장 중 하나를 가진다. 플랫폼 동등성 테스트의 비교 대상이다.
- **애니메이션 설정 (Motion Settings)**: 방향 모드, 레이아웃·회전·페이드 각각의 타이밍, 활성 여부, 동작 줄이기 무시 여부, 첫 표시 애니메이션 여부.
- **그룹 (Group)**: 위치 변화를 동기화하고 스크린리더 알림을 하나로 합치는 컴포넌트 묶음. 그룹원 순서(알림 순서)를 가진다.
- **접근성 라벨 (Accessibility Label)**: 숫자가 무엇인지 알려주는 짧은 이름(예: "할인액"). 알림과 보조기술 노출에 값 앞에 붙는다.
- **항목 식별자 (Item Identity)**: 리스트 재사용 시 "다른 항목"인지 판단하는 키.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 앱 개발자가 값과 포맷만 지정한 한 줄 선언으로 컴포넌트를 표시할 수 있다(샘플 앱에서 Android·iOS 각각 확인).
- **SC-002**: 지원 OS 범위(Android 7.0+ / iOS 15+)에 있는, 최근 3년 내 출시된 중급 기기에서, 전환 애니메이션 중(한 화면에 그룹으로 묶인 숫자 3개 동시 전환 포함) 60fps를 유지하고 프레임 드랍이 측정 구간의 1% 미만이다.
- **SC-003**: 이 문서의 모든 엣지 케이스와 수용 시나리오에 대해, 같은 표시 문자열 입력을 준 공통 테스트 세트로 두 플랫폼의 전환 계획이 100% 일치함을 확인한다. 또 지원 통화(KRW, USD, EUR, JPY)의 대표 로케일에서 두 플랫폼의 숫자·구분자 위치·부호가 일치함을 확인한다.
- **SC-004**: 스크린리더 사용 시, 단독 숫자는 한 번의 값 변경(빠른 연속 변경 포함)마다 최종 값이 정확히 1회만 낭독되고, 그룹은 한 번의 사용자 동작으로 여러 숫자가 바뀌어도 병합 알림이 정확히 1회만 낭독된다. 중간 값 낭독과 알림 잘림은 0회다.
- **SC-005**: 동작 줄이기가 켜진 상태에서 값 변경 후 다음 화면 갱신 안에 최종 값이 표시된다(애니메이션 프레임 0).
- **SC-006**: 애니메이션 중단·이어가기 시나리오에서 어떤 요소도 프레임 사이에 순간 이동하거나 중복 표시되지 않는다(프레임 캡처로 확인).
- **SC-007**: 리스트를 스크롤하면서 셀 재사용이 일어나도, 이전 항목의 값이 새 항목에 보이거나 잘못된 항목에 이벤트가 전달되는 경우가 0건이다.

## Assumptions

- 로케일 포맷은 각 OS 기본 규칙을 따르기로 결정했다(2026-11-09). 특정 로케일에서 플랫폼 간 차이가 실제 문제가 되면, 이후 버전에서 핵심 로케일만 라이브러리가 직접 규칙을 관리하는 방식으로 확장할 수 있다.
- MVP는 라틴 숫자(0–9)만 지원한다. 기본 숫자가 비라틴인 로케일도 라틴 숫자로 표시하고, 구분자·기호 규칙만 로케일을 따른다. RTL 레이아웃은 MVP 범위가 아니다.
- MVP는 각 플랫폼의 선언형 UI 환경만 대상으로 한다. 기존 뷰 시스템(Android View / UIKit) 지원은 이후 버전이다.
- 숫자는 한 번에 한 칸만 굴러간다(1 → 5는 중간 숫자 없이 바로 바뀜). 연속 모드와 자리별 최댓값(59 → 00)은 이후 버전이다.
- 과학·공학 표기, 숫자를 감싼 배경·테두리의 크기 전환, 결제/쿠폰 계산 로직은 범위 밖이다.
- 축약 표기의 단위와 경계는 로케일 규칙을 따른다(예: en-US 1,200 → "1.2K", ko-KR 1,200 → "1.2천", 13,000 → "1.3만"). 단위 경계를 개발자가 따로 정의하는 기능은 MVP에 없다.
- "자동" 방향은 숫자 값의 증감으로 판단하고, 포맷만 바뀐 경우(12.5 → 12.50)는 회전 없이 페이드만 적용한다.
- 화면 밖에 있는 동안의 값 변경은 애니메이션하지 않는다.
- 기본 타이밍 값(약 0.3~0.6초 안정)은 일반적인 모바일 마이크로 인터랙션 관행을 따른 것이며, 디자인 검토에서 조정할 수 있다.
- 숫자가 아니거나 무한대인 값은 정상 입력이 아니며, 마지막 유효 값을 유지한다.
